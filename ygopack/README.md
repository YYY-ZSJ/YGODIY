# 导出卡包（ygopack）

把 DIY 卡导出成 MDPro3 / ygopro 能直接加载的扩展包（`.ypk`）：

- **卡片资料**：来自 YGODIY 的卡片数据（「导出数据」的 JSON，或标签页里保存的卡），翻译成 cdb 的一行；
- **脚本**：Effect Model 生成的 Lua（萌卡 / MDPro3 方言）；
- **效果文本**：有 Effect Model 的卡用它生成的规范文本，保证和脚本一致；
- **卡图**：卡片数据里的原画转成 JPG，放进 `art/`（MDPro3 优先用这里的原画；找不到才从 `pics/` 的整张卡面里裁）。

导出后自动用测试沙盒（`sandbox/`）验证：像 MDPro3 一样加载这个包，逐张做加载检查，再跑清单里列出的情景。
通过了才会安装进 MDPro3 的扩展目录。

```
python -m ygopack 清单.json                 # 导出到清单旁边并验证
python -m ygopack 清单.json --install       # 验证通过后放进 MDPro3 的扩展目录（MDPro3 重启后生效）
python -m ygopack.mdpro3                    # 看自动找到的 MDPro3 与扩展目录
python -m ygopack.mdpro3 --set 路径         # 自定义：MDPro3 安装目录，或任意扩展目录（比如 ygopro2 的）
python -m ygopack.mdpro3 --clear            # 恢复自动查找
python -m ygopack.selftest                  # 导出器自检
```

`demo/` 是一个示例卡包「星光」：带检索效果的怪兽、通常怪兽、反击陷阱、同调怪兽各一张，附 3 个情景。

## 卡包清单

格式写在 `build.py` 开头。要点：

- 每张卡指向一份卡片数据（`card`）和一份 Effect Model（`effect`，通常怪兽可以不写）；Effect Model 里的 `card` 块
  （卡种、子类型、卡名、卡号）由导出器按卡片数据填，两边不会不一致。
- 卡号默认用卡面上的卡号，也可以在清单里写 `code`。
- 自己的字段写在 `setnames`（`"0xa01": "星光"`），每张卡的 `setcodes` 可以写字段名。

## 卡号

- 不能和 MDPro3 里已有的卡（官方卡库 + 扩展目录里的其他扩展）重复——导出时会对照检查；
- 不能超过 268435455：脚本里效果提示文字的编号是 `卡号×16+n`，要放得进 32 位；
- 一张卡有多个「1回合1次」的效果时，计数代码是 `卡号`、`卡号+o`、`卡号+o×2`……（9 位卡号 o=100，8 位 o=1），
  卡号挨得太近会和别的卡共用次数。导出时会检查并提示；示例卡包用 1000010xx 段、彼此隔开 100。
- DIY 衍生物（Effect Model 里「特殊召唤衍生物」没写卡号的）：卡号＝这张卡的卡号＋1、＋2……，导出时自动写进 cdb
  （通常怪兽·衍生物，名字、种族、属性、等级、攻守照效果里填的；没有脚本和卡图）。所以卡号段每张卡至少隔开衍生物的个数＋1。

## 找 MDPro3（`mdpro3.py`）

顺序：自定义路径 → 环境变量 `YGODIY_MDPRO3` → 桌面 / 开始菜单 / 任务栏里指向 `MDPro3.exe` 的快捷方式 →
注册表（卸载信息；系统记录的「运行过的程序」里只看 `MDPro3.exe` 这一项）→ 各本地硬盘根目录和第一层子目录里名字带 MDPro 的文件夹。
在本机这几条路各自都能找到 `D:\Game\MDPro3`。测试沙盒也用同一套查找。

自定义路径存在程序目录的 `平台设置.json`，不放进 `制卡器设置.json`：制卡器运行时会把后者整体读进内存再写回，
别处写进去的键会被覆盖掉。

## MDPro3 怎么读扩展（看 MDPro3 源码得出）

依据是 MDPro3 的最新源码（code.moenext.com/sherry_chaos/MDPro3，master 分支），已安装的 2026-09 版本与之一致。

- 扩展目录 `Expansions/` 下的散文件和 `*.ypk` / `*.zip` 里的文件都会读：`.cdb`、`.conf`、`script/c卡号.lua`、
  `art/卡号.jpg`、`pics/卡号.jpg`。扩展包里的脚本优先于官方 `script.zip`。
- **所有扩展包的文件放在同一张表里，按包内路径索引**：两个包里同名的文件只有一个能被看到。所以包内的 cdb、conf
  都用这个包自己的 id 命名（`<id>.cdb`、`<id>-strings.conf`），不用通行的 `strings.conf`（DataEditorY 打包时用的是这个名字，
  装两个这样的包就会互相遮住）。包内文件名一律 ASCII。
- **字段名的 bug**：读扩展字段名时调用 `ResourceManager.GetTextsByExtensions(".conf", 排除 "lflist")`，排除条件写反了，
  而且检查的是文件内容——结果只收「内容里含 lflist」的 conf。本机所有扩展的 conf（包括萌卡超先行卡包的）内容都不含这个词，
  所以 MDPro3 里任何扩展卡包的字段名都不显示。导出时多放一份 `<id>-mdpro3.conf`，内容里有一行含这个词的注释；
  MDPro3 修好以后标准版照常生效，两份都被读到时同一编号只认第一个，不冲突。文件名不能以 `lflist.conf` 结尾，否则会被当成禁限卡表。
  导出验证会模拟三种读法（现在的、按内容修好的、按文件名修好的），确认包里用到的字段在每种情况下都有名字。
- 启动时读一次，装进新包后要重启 MDPro3。

## 写 cdb（`cdb.py`）

开发环境用标准库 sqlite3。YGODIY 打包的 Python 没有带 sqlite3 模块，那时自动改用 Windows 10 起系统自带的
`winsqlite3.dll`；自检确认两条路写出的内容完全相同。
