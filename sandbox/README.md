# 测试沙盒

在 Python 里驱动 ygopro-core 跑真实对局：摆好场面 → 按步骤操作（发动、连锁、选卡、攻击、结束回合）→
检查场面（卡在哪、攻击力、基本分、效果是否被无效、抽了几张……）。
它是平台路线里「测试沙盒」的第一块，眼下用来验证 Effect Model 生成的 Lua；以后接上界面就是 YGODIY 里的「试打」，
再往后对 AI 也在它上面做。

目前直接用 MDPro3 自带的 `ocgcore.dll`、`script.zip`、`cards.cdb`（MDPro3 的位置与导出卡包用同一套自动查找，
见 `ygopack/mdpro3.py`；`YGODIY_MDPRO3` 环境变量可以直接指定）——和导出卡包后实际打牌的环境完全一致。以后换成 YGODIY 自己 fork 的 ygopro-core 只需改 `core.py`。

## 文件

| 文件 | 内容 |
| --- | --- |
| `core.py` | ctypes 绑定；引擎要脚本 / 卡片资料 / 报错时的三个回调；可以用 `overrides` 把某张卡的脚本换成别的；`add_expansion` 像 MDPro3 一样加载扩展包（.ypk / .cdb） |
| `probe.py` | 加载检查：把一张卡放进各区域推进到主要阶段，看脚本能否加载、注册、做发动检查 |
| `messages.py` | 解析引擎的消息流（70 多种消息，含所有需要应答的选择类消息） |
| `duel.py` | 一局对局：摆场、推进到下一个需要应答的时点、应答、查询某区域的卡 |
| `scenario.py` | 情景运行器：JSON 情景文件 → 摆场、执行动作、检查；格式写在模块开头的说明里 |
| `intents.py` | 意图式运行器：按实际提问兑现对象、分支、接受/拒绝，不要求模型预测select次数 |
| `test_data.py` / `test_templates.py` | 卡片情景验证、结果过期 / 从原文提取最低反向清单和参数模板 |
| `fixtures.py` / `worker.py` | 属性虚拟卡、四种固定辅助设施 / 单情景进程入口，无网络或AI配置 |

AI新工具使用意图格式，见`diy_workbench/ai/test_guide.md`；旧`scenario.py`格式保留，已有标准情景和变异不改写。产品异步桥接在`diy_workbench/ai/sandbox_process.py`：复制资源到临时目录，每情景独立进程、可取消，失败/异常不阻止后续情景。不会修改MDPro3原目录。

```
python -m sandbox.scenario 情景.json [-v] [--script 卡号=某个.lua]
```

`-v` 打印整个过程（回合、阶段、卡片移动、连锁、伤害、每次应答），情景写错时靠它排查。

## 情景怎么跑

- 玩家 0 先攻，可以第一回合攻击；开局不抽卡，双方卡组默认用 20 张青眼白龙填满，卡组不洗。
- 动作按顺序消耗：引擎问到某个玩家时，只有队首是该玩家的动作才会用上；其余提问用默认应答（不连锁、「是否发动」选是、
  选卡选前几张、区域选第一个空格、表示形式优先表侧攻击）。
- 检查默认在下一个「主要阶段 / 战斗阶段等操作」的稳定时点执行，也就是连锁全部处理完以后。
- 「连锁时能否发动」的检查会看到下一个稳定时点为止该玩家的所有连锁机会——一次召唤会带来「召唤中」「召唤成功后」两个时点，
  只看第一个会得出错误结论（变异测试就是这样把这个问题抓出来的）。

## 摆场为什么用 Debug.AddCard

ocgapi 的 `new_card` 不能给超量怪兽挂素材，也不会把卡标记成「在灵摆区域」。引擎残局模式用的 `Debug.AddCard`
两样都支持，所以摆场时生成一段 `Debug.AddCard(...)` 的 Lua，开局前用 `preload_script` 执行。

## MDPro3 带的 DLL 与源码包的差异

消息格式按 ocgcore 源码整理，但 MDPro3 实际带的 `ocgcore.dll` 与 MDPro3 源码包里的 ocgcore 并不完全一致，
实测发现的差异已在 `messages.py` 里处理：

- `MSG_SELECT_CHAIN`：头部没有 `forced` 字节，每个条目 14 字节（多 1 个字节的标志）。选择类消息总在缓冲区末尾，按剩余长度判断布局；
  只有 1 个条目时两种布局长度相同，以 MDPro3 的为准。
- `MSG_CONFIRM_CARDS`：玩家后面多 1 个字节。
- 给对方确认卡片之后引擎会返回「等待」，但并不需要应答（让客户端有时间展示），直接继续推进。
- 卡片资料里只要有 alias，引擎就改去加载 alias 那张卡的脚本（实测：alias 填卡号相近或相差很远的卡都是这样）。所以鹰身女郎1
  这类用 alias 表示「卡名当作……使用」的官方卡，官方脚本在这里跑不起来。导出的卡包 alias 一律写 0，
  测生成脚本时用 `Core.as_exported(卡号)` 照导出后的样子去掉 alias。

解析遇到对不上的长度会带着原始字节报错，不会猜着跳过。
