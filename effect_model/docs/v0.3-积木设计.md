# v0.3 真积木设计（草案，待确认）

2026-10-31。用户定下的方向：**积木贴近引擎，文本做辅助**。

## 1. 为什么改

v0.2 的「积木」其实是填空模板：一块对应官方的一句话，选好再填几个空。它保证了文字规范、脚本可靠，
但官方没写过的机制既没有说法也没有脚本，所以做不出来。

v0.3 改成真正的积木编程：少量通用积木，按引擎本身的结构分类，自由嵌套组合。
**能力上限 = 引擎（ocgcore）本身**；文字只负责让人看懂，不再限制能做什么。

## 2. 原则

1. **贴近引擎**：一块积木对应引擎里的一个结构或一个操作（效果类型、事件、效果代码、Duel 的一个动作……），
   不对应官方的某句话。
2. **文本辅助**：每块积木上写中文说明；拼好的效果实时读成一句中文；常见拼法换成官方说法；玩家可以手改卡面文字。
3. **形状管连接**：不同类型的积木形状不同，插不进不该插的地方。
4. **骨架管规则**：发动条件 / 代价 / 对象 / 处理各有固定的槽，游戏规则上不允许的拼法放不进去。
5. **能测**：拼出来的卡随时可以在沙盒里试打；原型阶段每种积木都配沙盒情景。

## 3. 积木的类型（形状）

| 类型 | 形状 | 是什么 | 例子 |
| --- | --- | --- | --- |
| 语句 | 方块，上下可接 | 做一件事 | 破坏、给卡片登记效果、让玩家选 |
| 控制 | C 形，可以包住语句 | 决定语句怎么执行 | 如果 / 否则、对每一张、那之后 |
| 卡片组 | 圆角长条 | 一组卡（可能 0 张） | 这张卡、对象、某区域符合条件的卡、刚才处理的卡 |
| 数值 | 圆块 | 一个数 | 1000、这张卡的攻击力、卡的数量、加减乘除 |
| 条件 | 六边形 | 是 / 否 | 比较、并且 / 或者 / 不是、存在、是怪兽卡 |
| 选项 | 下拉格（嵌在积木里） | 引擎的枚举值 | 玩家（自己 / 对方 / 双方）、区域、表示形式、种族、属性、期限 |

卡片条件（「4星以下的战士族怪兽」）是一种特殊的条件：针对「某一张卡」判断，用在卡片组积木的「什么样的卡」槽里。

## 4. 积木清单

右列是对应的引擎写法（萌卡一系 ygopro-scripts / ygopro-core），也是翻译成 Lua 的依据。

### 4.1 效果骨架（帽子块）

一张卡由若干个「效果」帽子块组成。帽子块上的选项直接对应 `Effect.CreateEffect` 之后的各项设置：

| 选项 | 中文 | 引擎 |
| --- | --- | --- |
| 效果类型 | 魔陷的发动 / 起动 / 诱发（选发、必发）/ 诱发即时 / 永续（单体、场地）/ 不入连锁的「每次……」 | `SetType`：`EFFECT_TYPE_ACTIVATE`、`IGNITION`、`TRIGGER_O/F`+`SINGLE/FIELD`、`QUICK_O/F`、`SINGLE`、`FIELD`、`CONTINUOUS` |
| 事件 | 自由时点、召唤成功、送去墓地、攻击宣言、连锁发动、阶段…… | `SetCode(EVENT_*)`（引擎 76 种） |
| 在哪生效 | 手卡、怪兽区、魔陷区、墓地、除外…… | `SetRange` |
| 影响范围 | 自己 / 对方的哪些区域（场地型永续用） | `SetTargetRange` |
| 次数 | 1 回合 N 次；这张卡 / 这个卡名 / 表侧期间 | `SetCountLimit` |
| 性质 | 取对象、伤害步骤也能发动、不会被无效…… | `SetProperty(EFFECT_FLAG_*)` |
| 分类 | 破坏、除外、特殊召唤……（给 AI 和「是否连锁」判断用；可由处理里的动作自动算出） | `SetCategory(CATEGORY_*)` |

帽子块下面有四个槽，对应引擎的四个函数：

| 槽 | 引擎 | 能放什么 |
| --- | --- | --- |
| 发动条件 | `SetCondition` | 条件积木 |
| 代价 | `SetCost` | 只能放可以当代价的动作（丢弃、解放、支付基本分、送墓、除外、取除素材 / 指示物） |
| 对象 | `SetTarget` 的取对象部分 | 「取对象」积木（只有这里能取对象） |
| 处理 | `SetOperation` | 语句、控制 |

永续效果（单体 / 场地）没有代价、对象、处理槽，改成「效果代码 + 数值 + 适用于哪些卡」，见 4.4。

### 4.3 登记效果（语句）：让卡或玩家「一段时间内」怎样

引擎里所有持续的东西都是「效果代码 + 数值 + 期限」。v0.3 不再一个一个挑，而是直接开放：

| 积木 | 引擎 |
| --- | --- |
| 给 [卡片组] 登记 [效果代码] [数值]，期限 [……] | 单体效果 `EFFECT_TYPE_SINGLE` + `RegisterEffect` |
| 让 [玩家] 适用 [效果代码] [针对什么卡]，期限 [……] | 场地 / 玩家效果 `EFFECT_TYPE_FIELD` + `EFFECT_FLAG_PLAYER_TARGET` + `Duel.RegisterEffect` |
| 在 [阶段 / 第 N 次……] 时做：[语句] | 延时效果（`EVENT_PHASE` + 标记） |

- **效果代码**：引擎的 259 种全部可选，按类别分组、每种写中文（本机常量表里本来就有中文注释），常用的排在前面：
  攻击力 / 守备力增减与变成、等级、不会被战斗 / 效果破坏、不能成为对象、不受效果影响、不能攻击 / 直接攻击、
  贯通、多次攻击、不能特殊召唤 / 召唤 / 发动 / 盖放、不能作为素材、离场时去向改变、效果无效……
- **数值**：数字积木，或「函数」——比如「这张卡的超量素材数 ×200」。
- **期限**：一直（离场前）、这个回合、到下个回合结束、只要这张卡在场上……对应 `SetReset`。

v0.2 里的永续、自肃、后果、一段时间内适用，在 v0.3 都是这两块积木换不同的效果代码和期限。

### 4.4 永续效果（帽子块的一种）

「永续效果」帽子块直接带：效果代码、数值、适用于哪些卡（卡片条件）、在哪生效、条件。
比如「只要这张卡在怪兽区域存在，自己场上的战士族怪兽攻击力上升 300」=
永续（场地型）· 在怪兽区生效 · 影响自己怪兽区 · 卡片条件「战士族」· 效果代码「攻击力增减」· 数值 300。

### 4.5 卡片组

| 积木 | 说明 | 引擎 |
| --- | --- | --- |
| 这张卡 | | `e:GetHandler()` |
| 对象 | 「对象」槽里取的卡 | `Duel.GetFirstTarget` / `GetChainInfo` |
| 那个发动的卡 / 那些召唤的怪兽 / 攻击的怪兽 | 和事件有关的卡 | `re:GetHandler()`、`eg`、`Duel.GetAttacker` |
| 全部 [谁的] [哪里] [什么样的卡] | 不选，全部 | `Duel.GetMatchingGroup` |
| 让 [玩家] 选 [N] 张 [谁的] [哪里] [什么样的卡] | 处理时选（不是取对象） | `Duel.SelectMatchingCard` |
| 刚才处理的卡 | 上一个动作实际动了的卡 | `Duel.GetOperatedGroup` |
| 变量 A | 之前记下的卡 | Lua 局部变量 |
| [卡片组] 里 [什么样的卡] / 合并 / 排除 | 集合运算 | `Group:Filter` / `Merge` / `Sub` |

### 4.6 数值与条件

- 数值：数字；某张卡的攻击力 / 守备力 / 等级 / 阶级 / 连接 / 原本数值；卡片组的数量；卡片组攻击力合计；
  基本分；加减乘除、一半；变量。
- 条件：比较（= ≠ < ≤ > ≥）；并且 / 或者 / 不是；卡片组「存在」「为空」；某张卡「是……」（卡种、种族、属性、
  字段、卡名、表示形式、在哪里、谁控制、是怎么召唤的）；自己 / 对方的回合；现在的阶段；这个回合做过……（活动记录）。

### 4.7 控制

| 积木 | 说明 |
| --- | --- |
| 如果 [条件] / 否则 | |
| 对 [卡片组] 里的每一张 | 逐张处理 |
| 重复 [N] 次 | |
| 那之后 | 前一步做成了才做下一步，且不同时处理（`Duel.BreakEffect`） |
| 可以选择做 [语句]（问玩家） | 「那之后，可以……」（`Duel.SelectYesNo`） |
| 让 [玩家] 从选项里选一个 | ●选项效果（`Duel.SelectOption`） |
| 记作 [变量] | 把卡片组 / 数值存起来 |

## 5. 规则护栏（骨架和形状保证的）

- 取对象只能在「对象」槽；处理里只能「让玩家选」。
- 代价槽只接受能当代价的动作，并自动按「代价」规则执行（`REASON_COST`、发动前检查能不能付）。
- 能否发动的检查自动生成：处理里每个不在「可以选择做」里的动作，都要求发动时有卡可以处理。
- 「那之后」「，」「并」三种连接的规则（是否依赖前一步、是否同时处理）由控制积木决定，不靠玩家理解。
- 积木形状不对插不进去；选项格只能选引擎有的值。
- 拼不出规则上不存在的东西，但能拼出「规则上合法、官方没做过」的东西——这正是要的。

## 6. 文本怎么辅助

1. **积木上的中文**：每块积木、每个选项都有中文，效果代码显示引擎常量表里的中文注释，必要时补充说明。
2. **实时读句子**：拼好的效果按积木树逐块读成中文，显示在积木旁边。每块积木有自己的读法，组合后通顺即可，
   不保证是官方说法。
3. **官方说法**：v0.2 的中文生成器保留下来，改成「认出常见拼法」——积木树匹配到某种官方句式时，输出官方说法
   （「这个卡名的效果1回合只能使用1次」「这个效果的发动后，直到回合结束时……」）。
4. **手改**：卡面文字最终由玩家决定，可以直接改；改过的文字不再自动覆盖，界面提示「文字和积木读出来的不同」。

## 7. 数据格式

积木树存成 JSON（v0.3 的 Effect Model），每个节点 `{"block": 积木名, 选项…, 槽: [子节点…]}`，例如增援：

```json
{"block": "effect", "type": "activate", "event": "free_chain",
 "operation": [
   {"block": "let_select", "player": "you", "count": 1, "as": "A",
    "from": {"block": "cards", "who": "you", "where": ["deck"],
             "filter": {"block": "all_of", "items": [{"block": "is_monster"}, {"block": "race", "value": "warrior"},
                                                    {"block": "level", "op": "<=", "value": 4}]}}},
   {"block": "to_hand", "cards": {"block": "var", "name": "A"}, "confirm": true}]}
```

翻译成 Lua 是逐块的：每种积木一个翻译函数，输出它对应的引擎调用；卡片组积木输出一个 Group 变量，
卡片条件积木输出过滤函数。v0.2 的模型可以自动转成 v0.3 积木树（旧存档和 61 张样例都能读进来）。
