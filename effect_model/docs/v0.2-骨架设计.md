## 0. 为什么要先改骨架

v0.1 的问题不只是词少，而是很多关键区别**没有地方放**，只能靠生成器猜，或者干脆表达不了：

| v0.1 的现状 | 后果 | v0.2 |
| --- | --- | --- |
| 「时」还是「场合」由事件推断 | 把「时」写成「场合」会多开发动窗口（易错规则第 3 条） | `timing` 必填 |
| 次数限制只有「这张卡 / 这个卡名」两种 | 「各1次」「任意一个1次」「同名卡只能发动1张」「表侧存在期间1次」「决斗中1次」分不清 | 卡片级 `limits`：计什么 × 按什么 × 多久重置 |
| 连接词 4 个标签混了两件事 | 「并且」和「那之后」都依赖前项成功，区别在是否同时处理 | `link` 按「依赖 × 先后」两个维度定义 |
| 谁选卡、谁执行、对谁生效是一回事 | 「对方必须把……除外」「双方各自选……」写不出 | 步骤有 `by` 和 `chooser` |
| 持续时间只有 3 种 | 「第2次的自己准备阶段」「第20回合的回合结束时」「下次的对方抽卡阶段」写不出 | 通用的期限对象和 `schedule_operation` |
| 绑定只在一个效果里有效 | 星尘龙「为那个效果发动而解放的这张卡」要跨效果、跨时点引用同一张卡 | `keep` 让绑定在别的效果里可用 |
| 召唤只有 4 种素材写法 | 接触融合、替代超量、「不能同调召唤」、「等级差」、对方怪兽当素材都写不出 | `summon` 分素材行、正规出场、手续、限制、许可 |
| 永续效果和「这个回合……」的效果是两套 | 技能抽取（持续检查）和效果遮蒙者（处理时确定）这种区别没地方放 | 统一的 `apply`，带 `scope` 与期限 |

不变的原则：模型描述**规则文字**而不是引擎 API；同一份数据生成文本与 Lua；封闭词汇表加自定义 Lua 出口；行为用测试沙盒验证。

## 1. 总体结构

```text
卡 ─┬─ card       身份：卡密、卡名、卡种、子类、灵摆刻度、规则上的同名
    ├─ summon     出场规则（效果外文本）：素材行、能否通常召唤、正规出场、特殊召唤手续、素材限制与许可
    ├─ rules      不编号的规则文字：发动从手卡也能用、发动后留在场上……
    ├─ counters   这张卡用的指示物种类与上限
    ├─ limits     次数额度 → 生成「这个卡名的①②的效果1回合各能使用1次。」或「1回合1次，」
    └─ effects[]  效果，按文本栏（怪兽 / 灵摆）和卡面顺序
         ├─ 发动部分：type · range · on + timing · window · condition · limit · restrict · cost · target · declare · modes
         └─ 处理部分：do[] 步骤 = act + 选卡器 + link（依赖 × 先后）+ by / chooser + as（绑定实际结果）

公共部件：选卡器（含引用与快照）、数值表达式、期限、持续适用 apply
```

编号①②、标题行、素材行、「●」列表、连接词的措辞都由生成器根据结构算出来，模型里不存文字。

## 2. 各部分

### 2.1 card：身份

```jsonc
"card": {"code": 91932350, "name": "鹰身女郎1", "kind": "monster", "subtypes": ["effect"],
         "rule_names": [76812113],   // 规则上当作「鹰身女郎」：构筑和对局都适用，效果无效也不影响
         "archetype_exceptions": [],  // 卡文明写的「当作 / 不当作某字段」
         "scale": 9}                 // 灵摆刻度（灵摆卡才有）
```

规则同名（`rule_names`）和「只要这张卡在场上表侧表示存在，卡名当作……」（持续适用 `change_name`，只在指定区域有效）分开存放（难点 09）。

### 2.2 summon：出场规则

```jsonc
"summon": {
  "materials": {"method": "fusion", "list": [{"name": 70095154}, {"filter": [{"race": "machine"}], "min": 1}]},
  "normal_summon": false,             // 「这张卡不能通常召唤」
  "proper": "only",                   // 正规出场：must_first「必须先用……方法出场」/ only「只能用……方法特殊召唤」
  "cannot": ["synchro"],              // 「这张卡不能同调召唤」
  "limit": "l9",                      // 「这个卡名的怪兽1回合只能特殊召唤1只」（额度 unit: special_summon）
  "procedures": [                     // 不入连锁的出场手续
    {"id": "p1", "kind": "contact",   // special 特殊召唤手续 | contact 接触式 | xyz_overlay 在怪兽上重叠超量
                                      // | normal 召唤手续（不用解放召唤、一只当作两只解放、用魔陷解放……）
     "from": ["extra"], "cost": [], "condition": [], "limit": "l0",
     "materials": {"where": {"who": "both", "where": ["mzone"]}, "destination": "grave", "record_as": "materials"}}
  ],
  "restrictions": [{"cannot_be_material": "fusion"}, {"cannot_special_summon_from": ["deck"]}],
  "material_permissions": [{"for": "link", "who": "opp", "where": ["mzone"], "count": 1}]
}
```

- 素材行按召唤法各有写法：融合是 `list`；同调是 `tuner` + `nontuner`；超量是 `filter` + `level` + `count`；连接是 `filter` + `min` / `max`。
  非标准的数值关系（勾陈一的「等级差直到1为止」）用选卡器的 `relation`。
- 出场手续不是效果：不入连锁，召唤无效的窗口也不同（易错规则第 18 条）。手续里的丢弃、送墓不是发动代价（难点 14 的霍普德拉古恩）。
- 「这张卡可以……从手卡特殊召唤」这类手续在卡面上是**编号的**（黑魔女 迪亚贝尔斯塔尔的①、电子龙的①），要和效果一起排编号，
  所以写在 `effects` 里，`type: "procedure"`；`summon.procedures` 只放不编号的（接触融合、替代超量、额外卡组的特殊召唤手续）。
  两种在 Lua 里是同一种写法（实施时修正，2026-10-29）。
- 苏生限制由 `proper` 加手续推出，生成器自动写 `EnableReviveLimit` 与特殊召唤条件（易错规则第 20、21 条）。

### 2.3 rules：不编号的规则文字

```jsonc
"rules": [
  {"rule": "activate_from_hand", "condition": [{"cond": "card_count", "sel": {"who": "you", "where": ["field"]}, "cmp": ["==", 0]}]},
  {"rule": "lasting", "turns": 3, "count_on": "opp"}
]
```

放效果外的、不编号的规则文字：「这张卡的发动从手卡也能用」「发动后继续留在场上」「这张卡的发动不能被对应」，以后还有效果外的胜利条件、维持代价等。

### 2.4 limits 与 restrict：次数额度、誓约、制约

**额度**是卡片级的，效果用 id 引用；一个效果可以同时受几个额度约束（鲜花女男爵②：卡名每回合 1 次，同时表侧存在期间 1 次）。

```jsonc
"limits": {
  "l1": {"scope": "card", "per": "turn", "n": 1},                          // 1回合1次，（这张卡）
  "l2": {"scope": "name", "per": "turn", "n": 1},                          // 这个卡名的……1回合只能使用1次
  "l3": {"scope": "face_up", "n": 1},                                      // 只在这张卡表侧表示存在才有1次
  "l4": {"scope": "name", "per": "turn", "n": 1, "unit": "activate_card"}, // 这个卡名的卡在1回合只能发动1张
  "l5": {"scope": "name", "per": "duel", "n": 1}                           // 决斗中只能1次
}
"effects": [{"id": "e1", "limit": "l2"}, {"id": "e2", "limit": ["l2", "l3"]}]
```

| 写法 | 表达 |
| --- | --- |
| ①②的效果1回合各能使用1次 | 两个 name 额度，各自被一个效果引用（生成器合成一行标题） |
| ①②的效果1回合只能有1次使用其中任意1个 | 一个 name 额度，被两个效果引用 |
| 1回合1次 / 每回合 n 次 / 同一连锁上只能1次 / 每个战斗阶段1次 | `scope: "card"`，`n`，`per: "chain"`，`per: {"phase": "battle"}` |
| 发动与使用的区别（发动被无效后算不算） | `unit`：`use`（默认）/ `activate_card` / `procedure`（手续自己的次数）/ `special_summon`（同名怪兽的特殊召唤次数） |

**次数 `n`** 默认 1，可以改成多次（2026-10-29，工作台的「次数」一栏可以填）。多次时的写法照官方卡：

| 额度 | n = 1 | n = 2（例） | 官方例卡 |
| --- | --- | --- | --- |
| 这张卡 | 「1回合1次，」 | 「1回合最多2次，」 | No.15 机关傀儡-巨人杀手、蜂军风、三幻魔的失乐园 |
| 这个卡名的效果 | 「1回合只能使用1次」 | 「1回合可以使用最多2次」 | No.80 狂装霸王 狂想战曲王、机炮食人魔（3次） |
| 这个卡名的卡的发动 | 「在1回合只能发动1张」 | 「在1回合可以发动最多2张」 | 杀手级调整曲同调 |
| 特殊召唤手续 | 「的方法的特殊召唤1回合只能有1次」 | 「……1回合可以有最多2次」 | 没有官方先例，按同一句式类推 |
| 表侧表示存在期间 | 「只在这张卡表侧表示存在才有1次」 | 「……才有2次」 | 没有官方先例 |

几个效果次数不同时分开写：「这个卡名的①的效果1回合可以使用最多2次，②的效果1回合只能使用1次。」
Lua 是 `SetCountLimit(n[,计数代码])`；一个效果同时受几个额度约束时，引擎只能挂一个次数，取最少的。
重叠超量的「1回合1次」用记号计数，n 次就是记号少于 n。`devtools/check_limits.py` 用 DIY 测试卡在沙盒里确认
能用 n 次、第 n+1 次不行，并带「改回 1 次」的对照。

**誓约与制约**（`restrict`）挂在效果上，关键是**从什么时候开始算**（易错规则第 13 条）：

```jsonc
"restrict": [{"span": "whole_turn",          // whole_turn 整个回合，发动前做过也不能发动 | after_resolution 处理后到回合结束 | while_applied 适用期间
              "who": "you", "forbid": ["summon", "flip_summon", "special_summon"],
              "except": {"by_effect": "this_card"}}]
```

`whole_turn` 需要检查发动前的行动记录，生成器用萌卡的活动计数器实现；文本按 span 选「这张卡发动的回合，自己……」还是「这个效果的发动后，直到回合结束时……」。

**自肃第一批**（2026-10-29，依据任务 7 的自肃调研：2,249 张 / 2,443 条候选，特殊召唤类占核心条款三成以上）：

```jsonc
"restrict": [{"span": "after_resolution",          // whole_turn | after_resolution（| while_applied 留给永续）
              "who": "you",                         // you 自己 | both 双方 | self 这张卡（「这张卡不能攻击」）
              "forbid": ["special_summon"],         // special_summon | summon | flip_summon | normal_summon | battle_phase | attack | direct_attack
              "from": ["extra"],                    // 只限从额外卡组特殊召唤
              "only": [{"race": "machine"}],        // 「不是机械族怪兽不能……」：选卡过滤条件，几条一起是「且」
              "except": {"by_effect": "this_card"}, // 「这张卡的效果以外」
              "until": "end_of_turn"}]              // end_of_turn | end_of_next_turn（「直到下次的自己回合的结束时」）
```

| 写法（全卡库多数） | 位置 | Lua（照官方脚本） |
| --- | --- | --- |
| 这个效果的发动后，直到回合结束时自己不是X怪兽不能从额外卡组特殊召唤 | 效果最后（259 张） | 处理最后登记 EFFECT_CANNOT_SPECIAL_SUMMON；处理中途 return 的也照样登记 |
| 这张卡的发动后，直到回合结束时…… | 卡的发动的效果最后（84 张） | 同上 |
| 这个效果发动的回合，自己不是X怪兽不能特殊召唤 | 效果最后（49 张） | 自定义活动计数 + 誓约（电子龙三型） |
| 这张卡发动的回合，自己不能进行战斗阶段 | 单独一行（47 张），有「这个卡名的卡在1回合只能发动1张」时并进那一行（35 张） | ACTIVITY_BATTLE_PHASE + EFFECT_CANNOT_BP 誓约 |
| 这个效果发动的回合，这张卡不能攻击 | 效果最后 | 这张卡的攻击宣言次数 + 单体誓约（混沌巫师） |
| 自己对「X」1回合只能有1次特殊召唤 | 单独一行（33 张） | `c:SetSPSummonOnce(id)`，存在 `summon.restrictions` |

被无效时照官方说明：整回合的是发动条件（卡的发动被无效才解除，只有效果被无效时仍然限制，强欲而谦虚之壶）；
处理后的发动或效果被无效都不建立，主要处理没成功仍然建立（卫星闪灵启辉器）。官方卡里能完整表达的只有休战增援
（样例与情景和官方脚本对照），其余写法用 DIY 测试卡检查（`devtools/check_restrict.py`）。还没做：「只能是」的「或」组合
（巨大喷流卫星闪灵）、只在走了某个分支时才限制（召唤女巫）、发动以外的动作（效果发动、作为素材、抽卡……）。

### 2.5 效果的发动部分

```jsonc
{"id": "e2", "block": "monster",                 // monster | pendulum（灵摆效果栏，各栏单独编号）
 "type": "trigger",                              // activation 卡的发动 | ignition | trigger | quick | flip | continuous | procedure（编号的召唤手续）
 "optional": true,                               // 选发 / 必发（诱发与诱发即时都有必发）
 "range": ["grave"],                             // 在哪里发动 / 适用；省略时按卡种与类型推断
 "on": {"event": "sent_to_gy", "subject": {"ref": "self"}, "from": ["mzone"], "reason": ["battle", "effect"]},
 "timing": "when",                               // when「……时」/ if「……的场合」；有事件就必填
 "window": {"turn": "any", "phases": ["standby"], "damage_step": "no"},
 "condition": [{"cond": "card_count", "sel": {}, "cmp": [">=", 1], "at": "both"}],
 "limit": "l1", "restrict": [],
 "cost": [{"act": "release", "what": {"ref": "self"}, "as": "released", "keep": "this_turn"}],
 "target": [{"as": "t", "sel": {}, "recheck": "relation"}],
 "declare": [{"as": "named", "kind": "card_name", "domain": {"who": "you", "where": ["deck"]}}],
 "modes": {"choose": 1, "at": "activation", "options": []},
 "do": [],
 "cannot_be_negated": false, "response_lock": null,
 "granted_to": null,                             // 给别的卡的效果：equipped（装备怪兽）| {"xyz_host": 过滤} | 选卡器
 "both_players": false}                          // 双方都能发动（场地魔法等）
```

- **事件 `on`**：一个事件键加修饰参数（主体、来源区域、原因、执行者、`by_effect`「被这张卡③的效果除外的场合」、召唤法、卡种、`includes`「包含某类处理的发动」、`where`「相同纵列」）。修饰不展开成新的事件键（调研的粒度约定）。
  几个事件任一发生都诱发时 `event` 写成列表（「这张卡召唤·特殊召唤的场合」= `["normal_summon_success", "special_summon_success"]`）。
  `reason` 是集合：「作为素材」和「被效果送去墓地」可以同时成立（易错规则第 29 条）。
- **`timing` 必填**，不再推断（第 3 条）。阶段类事件（「结束阶段才能发动」）不写。
- **`window`** 写可发动的窗口：回合、阶段、伤害步骤里的子区间（欧尼斯特的「从伤害步骤开始时到伤害计算前」写成 `{"phase": "damage_step", "from": "start", "to": "before_calc"}`）。
  一般的诱发即时效果能不能在伤害步骤用，由 `damage_step` 单独写明，lint 按规则检查是否允许（第 27 条）。
- **条件**每条带 `at`：只在发动时查 / 只在处理时查 / 都查（第 25 条）；用 `all` / `any` / `not` 组合，不靠标点猜。
- **代价**是动作列表，全部都要支付；「从以下选一种支付」写成列表里的 `{"choose": [[…], […]]}`；数量可变时用 `count` 的上下限，`as` 记住实际支付的。
- **对象**在发动时确定；`recheck` 写处理时要重查什么（默认只查「与效果的关联」，电子龙·无限②的「表侧攻击表示」只在发动时要求）。
  处理时才选的卡不进 `target`，写在步骤的选卡器里（第 1 条）。
  永续魔法陷阱那种「只要这张卡在场上，作为对象的怪兽……」，对象带 `"keep": "while_related"`，永续效果引用它。
- **`granted_to`**：「装备怪兽得到以下效果」「持有这张卡作为超量素材的怪兽得到以下效果」——效果本身照常写，只是由别的卡发动 / 适用；处理中给效果用动作 `grant_effect`，内层是同样的效果结构。
- **`declare`**：发动时宣言的卡名、种族、属性、数字，和对象一样在发动时确定、处理时引用。
- **`modes`**：「●」列表。每个选项可以有自己的事件和时机（神之通告的两个 ● 回应的东西不同），`at` 写在发动时还是处理时选。
- **`cannot_be_negated` / `response_lock`**：「这个效果不会被无效化」「这张卡的发动不能被对应」「不能对应这张卡的发动让怪兽的效果发动」。

### 2.6 效果的处理部分：步骤

```jsonc
{"act": "discard",                           // 动作
 "what": {"who": {"ref": "p"}, "where": ["hand"], "count": 1, "chooser": {"ref": "p"}},
 "link": "then",                             // 和前一步的关系，见下表
 "optional": false,                          // 「可以……」：玩家决定做不做
 "by": "opp",                                // 由谁执行（「对方必须……」：卡的抗性不挡玩家的行为）
 "for_each": {"players_of": {"ref": "drew"}}, "each_as": "p",   // 对每个玩家 / 每张卡分别处理（默认同时）
 "if": {"cond": "die_coin_result", "of": {"ref": "coin"}, "called_right": true},
 "timing": "after_resolution",               // 效果处理后立即进行的召唤（第 19 条）
 "partial": "allowed",                       // 多张对象里有的已不合适：allowed 剩下的照做 | none 全部不处理
 "as": "x"}                                  // 绑定这一步**实际**处理成功的卡，后面「这个效果……的卡」引用它
```

暂时除外写在除外动作上：`{"act": "banish", "return_at": {"phase": "end", "which": "this_turn"}}`，回来不算特殊召唤。

**连接**按调研和 PSCT 的两个维度定义：

| link | 依赖前项成功 | 与前项同时 | 中文常见写法 | 英文 |
| --- | --- | --- | --- | --- |
| `and_if_you_do` | 是 | 是 | 「，」「并」 | and if you do |
| `then` | 是 | 否 | 「。那之后，」 | then |
| `also`（默认） | 否 | 是 | 「。」「，」 | also |
| `also_after_that` | 否 | 否 | 少见，逐卡核对 | also, after that |
| `and` | 互为条件 | 是 | 少见 | and |

中文标点不是一对一的（任务 3 的 `text.conjunction_punctuation`），所以模型存语义，措辞由生成器按语境选。

还有几种不是单纯动作的步骤：`select`（只选、不做事，「双方各自选自身场上1只怪兽」）、`branch`（按结果分支：猜中的场合 / 猜错的场合）、
`one_of`（「加入手卡或特殊召唤」）、`apply_continuous`（让一段持续内容开始适用）、`schedule_operation`（预约以后的处理）、`raw`（自定义 Lua 出口）。

### 2.7 选卡器与引用

```jsonc
{"who": "opp",                         // 控制者；"owner" 另写持有者
 "where": ["field"], "face": "up", "position": "faceup_attack",
 "filter": [{"level": ["<=", 4]}, {"set": "魔弹", "setcode": "0x108"}, {"not": {"name": 65518099}}],
 "count": 1,                           // 数字 | "all" | {"min": 1, "max": 3} | {"until_equal": 表达式}
 "except": [{"ref": "self"}],
 "chooser": "opp",                     // 由谁选（默认效果的控制者）
 "random": false,                      // 随机选（「随机选1张手卡」）
 "extreme": null,                      // {"max": "atk"}「攻击力最高的怪兽」，并列时全部算
 "relation": {"same": ["name"]}}       // 集合关系：same / different / sum / roles（各几只）/ diff
```

- 过滤条件是单张卡的谓词，`all` / `any` / `not` 组合；「原本的」数值、移动前的状态（`previous`）、原因、能否被执行某动作（`can`）都是谓词。
- **集合关系**（`relation`）和单卡过滤分开：卡名不同、种族相同、等级合计、「调整1只和调整以外1只，等级差1」（难点 21、13）。
- **引用**：`self`、对象 / 宣言 / 步骤的 `as` 名字、`chain`（正在回应的那个发动）和 `chain.card`、`event`（触发事件的那些卡）、
  `battle.you` / `battle.opp`（正在战斗的双方怪兽）、`materials`（这张卡出场时用的素材）、`overlay`（超量素材）、`e1.released`（别的效果用 `keep` 留下的绑定）。
- **快照**：引用可以带 `"snapshot": "cost" | "event" | "activation"`，取那个时点的卡名、数值（百眼龙复制的是「为发动而除外的那只」当时的信息；
  魔弹射手卡斯帕比较的是「那张发动的卡」的卡名）。默认取处理时的当前值。

### 2.8 数值表达式

```jsonc
300
{"count": {"ref": "overlay"}}
{"stat": "atk", "of": {"ref": "battle.opp"}, "original": false}
{"sum": "atk", "of": {"ref": "d", "filter": [{"previous": {"face": "up"}}]}}
{"mul": [{"count": {"ref": "materials"}}, 1000]}   // 还有 add / sub / half（带 round）/ max / min / lp
```

攻守、伤害、回复、数量、仪式等级等需要数值的地方都用它，不再为「×连接区怪兽数」「对方怪兽的攻击力数值」各造一个词。

### 2.9 期限与预约

```jsonc
"until": "end_of_turn"                                       // 也有 end_phase、end_of_next_turn、permanent
"until": {"next": "draw", "player": "opp"}                   // 下次的对方抽卡阶段
{"act": "schedule_operation", "activates": false,            // 到时直接处理（不入连锁）还是作为效果发动
 "at": {"phase": "standby", "player": "you", "nth": 2, "count_from": "activation"},
 "do": [{"act": "add_to_hand", "what": {"ref": "x"}}]}
"reset_on": ["leave_field", "face_down", "control_change"]   // 额外的提前解除条件
```

「第2次的自己准备阶段」「以发动的回合为第1回合来计算的第20回合的回合结束时」「这个效果特殊召唤的怪兽在结束阶段破坏」都是 `schedule_operation`，
它记住的是被这个效果处理的**那一张卡**（难点 18）。

### 2.10 持续适用 apply

永续效果和「直到回合结束时……」共用同一个结构：

```jsonc
{"cont": "effects_disabled",                 // 持续内容，对应调研的 cont.* 词条
 "affects": {"who": "both", "where": ["mzone"], "face": "up"},
 "scope": "dynamic",                         // dynamic 持续检查范围（技能抽取）| fixed 处理时确定的那些卡
 "value": 300, "from": {}, "which": []}      // 各内容自己的参数：数值、来源过滤（抗性）、受限对象（禁止）
```

- 永续效果：`{"type": "continuous", "apply": {...}}`，适用条件默认是「这张卡在 range 里表侧存在」。
  一句话同时给几种许可时 `apply` 写成列表，每项仍是一个调研词条（魔弹射手 卡斯帕的「把「魔弹」魔法·陷阱卡从手卡发动」=
  `trap_from_hand` + `quickplay_opponent_hand`，渲染器合成一句）。
- 处理中开始的持续：`{"act": "apply_continuous", "apply": {...}, "until": ...}`。
- 「每次……，……」这类不入连锁的反应：`{"type": "continuous", "on": 事件, "do": [...]}`（王立魔法图书馆放指示物、增殖的G的抽卡）。
- 抗性写清来源：`immune_effect` 带 `from`（谁的、是否发动的、是否以这张卡为对象）；替代写清去向：`redirect_destination` 的 `from_dest` / `to_dest`。

**永续第一批**（2026-10-29，依据任务 7 的永续调研：114 个细项按脚本命中卡数排）。键是调研 id 去掉 `cont.`，写法照全卡库多数：

| cont | 参数 | 写法 | 官方样例（与官方脚本对照） |
| --- | --- | --- | --- |
| `def_update` | affects, value | 这张卡的守备力上升500；和 `atk_update` 一起写成列表是「攻击力·守备力上升500」 | — |
| `change_level` | affects, value（升降）或 set（变成） | 这张卡的等级上升2星 / 等级变成1星 | — |
| `indestructible_battle` | affects | 这张卡不会被战斗破坏 | — |
| `indestructible_effect` | affects, by: opp | 场上的这张卡不会被（对方的）效果破坏；和上一项列表并写「这张卡不会被战斗·效果破坏」 | — |
| `indestructible_count` | by: [battle/effect], n | 这张卡1回合只有1次不会被战斗破坏 / 1回合最多2次…… | 暗黑共鸣者 |
| `cannot_be_targeted` | affects, by: opp | 这张卡不会成为对方的效果的对象；和 `indestructible_effect` 并写「……，不会被对方的效果破坏」 | — |
| `piercing` | — | 这张卡向守备表示怪兽攻击的场合，给与攻击力超过那个守备力的数值的战斗伤害 | 枪兵龙人 |
| `direct_attack` / `cannot_direct_attack` | — | 这张卡可以直接攻击 / 这张卡不能直接攻击 | — |
| `extra_attack` | n | 这张卡在同1次的战斗阶段中可以作2次攻击 | 隼骑士 |
| `attack_all` | — | 这张卡可以向对方怪兽全部各作1次攻击 | 朱罗纪单脊龙 |
| `cannot_be_attack_target` | — | 对方怪兽不能选择这张卡作为攻击对象 | — |
| `attack_target_restriction` | only: self | 只要这张卡在怪兽区域存在，对方不能选择其他怪兽作为攻击对象 | — |
| （出场限制）`cannot_be_material` | fusion / synchro / xyz / link | 这张卡不能作为同调素材。（不编号，存在 `summon.restrictions`） | — |

这些内容也能用在处理中：「这个回合，那只怪兽不会被战斗·效果破坏」（`apply_continuous` + `until`）。
Lua 写法照官方：攻击相关是不带范围的单体效果，抗性与攻守等级变化带 SINGLE_RANGE + 怪兽区域，范围是一组卡时用 FIELD + 目标函数。
没有官方样例的各项用 DIY 测试卡检查（`devtools/check_cont.py`）。「代替破坏」要先补「可以选择代替」的结构，留到第二批。

### 2.11 履历与跨效果绑定

- `keep`：步骤的绑定在别的效果里也能用，并写明保留多久。星尘龙①的代价 `{"as": "released", "keep": "this_turn"}`，②引用 `e1.released`。
- 条件 `named_card_used`：「这张卡的①的效果适用的回合」，区分 `activated` / `applied` / `resolved`。
- 事件修饰 `by_effect`：「这张卡的③的效果除外的场合」。

生成器用萌卡的 flag effect 实现；模型只写语义。

### 2.12 文本层

- 规范生成：DIY 卡的文字一律从结构生成，用百鸽语体；同一意思有多种写法时用推荐写法（任务 3 的 `text.chinese_term_preference`）。
- 原文回放：对照官方卡时，文字只做规范化后比较；没有编号的旧式文本、地区差异只能原样保存，不承诺能重新生成（任务 3 的 `text.lossless_source_preservation`）。
- 标题行由 `limits` 和 `restrict` 推出；素材行由 `summon.materials` 推出；灵摆卡按块输出，块内单独编号。
- 导出到 MDPro3 时，灵摆卡文本按它的格式写「←刻度 【灵摆】 刻度→」；百鸽的写法是「【灵摆效果】」。
- 日文、英文：模板引用同一组参数（任务 3 的 `text.language_alignment`），渲染器以后再做，结构上已经够用。

### 2.13 交给生成器，不进模型

这些是规则或引擎的事，DIY 作者不需要选，模型里也不放：

- 效果分类 `CATEGORY_*` 与处理预告：从动作推出，灰流丽、屋敷童能不能回应全靠它；`modes` 只把本次选中的那个计入。
- `EFFECT_FLAG_DELAY`、`IsRelateToEffect`、王家长眠之谷、检索后给对方确认、连锁中特召的合并处理。
- 诱发效果发动前仍在发动区域（第 4 条）、可在手卡发动的自身特召诱发的连锁限制（第 6 条）、OCG 非公开区域选发的顺序（第 5 条）、
  处理中不能另开连锁（第 16 条）、2020 年后的额外卡组出场区域（第 26 条）、结束阶段的处理顺序（第 30 条）：由引擎负责，生成器不要写反。
- 誓约的活动计数、跨效果绑定和履历的 flag、预约处理的计数。
- **目标客户端能力表**：读用户 MDPro3 的 `constant.lua`，用到它没有的常量（比如 `EFFECT_CHANGE_CARD_TYPE`）就报警，不生成跑不起来的脚本。

## 5. 词汇与调研 id 的对应

- 约定：模型里的键 = 调研 id 去掉大类前缀。`act.destroy` 写作 `"act": "destroy"`，`cont.effects_disabled` 写作 `"cont": "effects_disabled"`，
  `event.sent_to_gy` 写作 `"event": "sent_to_gy"`。调研词典每一项都带三语模板、萌卡 Lua 写法、CATEGORY 策略和出处，实现某个词时直接照它写；
  任务 5 的频率用来排先后。
- 代价沿用动作的名字：`cost.detach_xyz` 写作 `detach_xyz_material`，`cost.return_to_hand` 写作 `add_to_hand`（来源是场上时措辞「回到手卡」）。
- 例外：
  - 只属于模型的结构：`select`、`branch`、`one_of`、`raw`。
  - `effect_activated` 用 `what: card | effect` 区分卡的发动与效果的发动（调研的同一个词条）。
  - 清单外的新发现：`act.activate_from_deck`（勾陈一「从卡组选1张……发动」）。实现时补进清单，并请调研方补依据。

## 6. 从 v0.1 迁移

`normalize` 继续接受 `ygodiy-effect/0.1`，读入时自动升级。15 张样例升级后生成的文本和 Lua 必须与现在**完全一样**，34 个情景照常通过，这是重构的第一道关。

| v0.1 | v0.2 |
| --- | --- |
| `type: summon_rule` | `effects` 里的 `type: procedure`（编号的召唤手续） |
| `type: activate` | `type: activation` |
| `type: rule` | `rules` |
| `summon: {method, ...}` | `summon.materials` |
| 效果上的 `limit: {scope, kind, group}` | 卡片级 `limits` + 效果的 `limit` 引用；`kind: activate`（誓约次数）→ 手续额度 |
| `box` | `block` |
| `from` | `range` |
| `timing` 可省略、按事件推断 | 升级时按 v0.1 的推断规则补上，之后必填 |
| `link: then / after / and / also` | `and_if_you_do` / `then` / `and_if_you_do` / `also`（v0.1 的 then 是「，」做到才继续，after 是「那之后」） |
| 事件 `summoned` / `special_summoned` / `activation` / `phase` / `targeted_for_attack` | `normal_summon_success` + `special_summon_success` / 带 `subject` 的 `special_summon_success` / `effect_activated` / `phase_window` / `becomes_attack_target` |

| 动作 `detach` / `set` | `detach_xyz_material` / `set_spell_trap`、`set_monster` |

工作台存档里的 `tab["diy"]["effect"]` 同样在读入时升级，不需要用户操作。

## 7. 暂不覆盖

- 自定义 Lua 出口保留：步骤 / 条件 / 过滤的 `raw`，以及整张卡手写。调研统计里只被 1～3 张卡用到的 237 种构件、2017 张有复杂自定义逻辑的卡，大部分会落在这里。
- 没有编号的旧式卡文只做原文回放，不生成。
- 邪神类特殊的攻守计算顺序（调研可信度低）。
- 2020 年以前的规则、TCG 与 OCG 不同的裁定（模型按 OCG 生成，差异以后在 lint 里提示）。
- Rush Duel、动画原创卡。
