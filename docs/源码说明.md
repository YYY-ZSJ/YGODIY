# YGODIY 源码说明（开发者）

源码入口为 `main.py`，依赖、资源准备和独立程序构建步骤见 [构建说明](构建说明.md)。原有 `fast_launch.py` 启动器仍可通过 `YGODIY_SRC` 加载这份源码。

## 模块

主体模块：

| 模块 | 内容 |
| --- | --- |
| `main.py` | 主窗口 `YuGiOhApp`：模式切换（含漫画卡模式）、程序入口 `main()`；最前面预载神经翻译模型 |
| `OTCG_widget.py` | OCG/TCG 编辑器 |
| `RD_widget.py` | Rush Duel 编辑器 |
| `Past_widget.py` | 旧版卡编辑器 |
| `FC_widget.py` / `CardBack_widget.py` | 场地中心卡、卡背编辑器 |
| `customComponents.py` | 自定义控件、对话框、文字组、符号按钮条、后台任务 |
| `CompressText.py` / `TextBreaker.py` / `mixTextItem.py` | 卡面文字排版（压缩、断行、描边渐变、日文注音） |
| `infoFetcher.py` | 卡片资料获取（先查离线卡库，再联网） |
| `config.py` | 各编辑器的配置数据类 |
| `utils.py` | 图片 / 字体解密（带缓存，资源路径会解析到打包目录）、图像工具函数 |
| `applog.py` / `startup.py` | 日志与崩溃保护；单实例保护、启动加载界面 |
| `runtime_paths.py` | 源码、独立程序与旧启动器共用的资源和用户数据路径 |
| `ygo_translator/` | 本地实例翻译和神经翻译的推理源码 |

功能子系统：

| 模块 | 内容 |
| --- | --- |
| `common.py` | 子系统共用的常量与小工具（控件读写、日志、缓存、调用原方法时裁掉多余参数等） |
| `card_library.py` / `card_search.py` | 离线卡库的加载、索引与搜索；卡名搜索对话框增强、高级搜索 |
| `card_tabs.py` | 卡包与标签页（`_CardTabManager`）：状态读写与历史、卡图缓存、撤销、卡包导出 |
| `editor_setup.py` | OCG / 旧版编辑器构造后的补充：清空演示卡、输入防抖、查卡竞态保护、灵摆刻度实时刷新等 |
| `effect_layout.py` | 效果文本排版（首行压缩、对齐、行高、字距）与「效果排版」对话框 |
| `rd_frame.py` | RD 卡框跟随 OCG 编辑器：把 OCG 的卡片数据同步到 RD 卡面、切到 RD 模式、阶级图标、效果文字排版 |
| `rd_panel.py` | RD 右栏按 OCG/TCG 的版式重排、补齐控件 |
| `rd_style.py` / `rd_ruby.py` | RD 文字样式、颜色、一键注音；卡面日文注音的摆放 |
| `rarity.py` | 罕贵度前景层、额外罕贵度（PSER2 / ORR）、罕贵下拉弹窗位置 |
| `overframe.py` | 超框卡图：可拖动图元、RD / OCG 多图层、两模式间同步 |
| `free_text.py` | 自定义文本 |
| `customization.py` | 自定义防伪与版权（下拉里可增删改名的自定义项） |
| `watermark.py` | 秘密水印在灵摆卡上向上延伸 |
| `manga.py` | 游戏王漫画卡模式：卡面绘制、选项条、独立右栏 |
| `mode_styles.py` | OCG/TCG、RD、漫画卡三模式各自的显示设置（随卡保存在 `_mode_styles`）、RD 语言下拉 |
| `language_switch.py` | 切换语言时翻译 / 还原效果文字、卡名按自己的语言绘制、「AI翻译」开关 |
| `app_window.py` | 程序图标、任务栏身份、窗口不超出屏幕 |
| `diagnostics.py` | 环境变量开启的诊断输出（`YGODIY_PERFORMANCE_DIAGNOSTIC`、`YGODIY_RD_DIAGNOSTIC` 等） |

子系统模块之间的引用放在各模块**末尾**导入（模块体只有定义，执行到末尾时本模块的定义都已就绪，循环引用也成立）；


### 挂钩

- **实例级挂钩**：标签页管理器（撤销、卡图是否改动）、RD 卡框同步、输入防抖、卡图缓存、查卡竞态保护等，
  是在编辑器构造完成后包装**实例**上的方法（信号此前已连到原方法上，与改类方法语义不同），
  由宿主 `__init__` 显式调用 `editor_setup._setup_otcg_editor` 等函数安装，顺序与原先一致。
- **显式装饰器**：几处「方法执行完后再做一件事」且原方法有多个 return 的，用写在宿主类里的装饰器表达，
  如 `@watermark._recheck_secret_watermark_after`、`@overframe._sync_ocg_layers_after`、
  `@card_tabs._restore_after_search_refetch`。
- 标签页管理器套用卡片数据时，为了只在最后重排一次卡面，会**临时**把编辑器实例上的
  `switch_base_image` / `update_card_name` / `update_text` / `transform_*` 换成空操作，套用完再换回并各调一次
  （`card_tabs._CardTabManager._apply_to_editor`）。卡片数据本身经 `OTCGWidget.apply_card_data` /
  `export_card_data` 读写。

## 平台模块

一站式 DIY 平台的部件。前三个是独立的包（可以单独用命令行跑）；`diy_workbench/` 把它们接进程序，
作为模式下拉里漫画卡后面的「DIY 工作台」。这些都是包，`main.py` 导入前把源码目录加到搜索路径末尾
（启动器的查找器只加载顶层模块）。

| 包 | 内容 |
| --- | --- |
| `effect_model/` | Effect Model：卡片效果的结构化描述，生成 ygopro Lua（萌卡 / MDPro3 方言）与规范中文效果文本，见其 README |
| `sandbox/` | 测试沙盒：在 Python 里驱动 ygopro-core 跑真实对局、按情景检查结果，见其 README |
| `ygopack/` | 导出卡包：卡片数据 + Effect Model → MDPro3 / ygopro 扩展包（.ypk），自动查找 MDPro3 的扩展目录，见其 README |
| `diy_workbench/` | DIY 工作台（只支持 OCG/TCG 卡）：效果页（填空写效果，实时出规范文本与 Lua，手动「写回卡面」，沙盒检查）、卡包页（卡片一览、作者 / 卡号段 / 自己的字段、导出并装进 MDPro3） |

工作台的数据随标签页存档：每张卡的效果（Effect Model v0.2，旧的 v0.1 存档读到时就地升级）与字段在 `tab["diy"]`，
卡包设置在 `pack["diy"]`。
`store.py` 负责卡片数据 ↔ Effect Model ↔ 导出清单，`vocab.py` 是界面上的填空词表，
`dialogs.py` / `effect_page.py` / `pack_page.py` 只管界面，`workbench.py` 负责接进主窗口、后台导出与验证。
